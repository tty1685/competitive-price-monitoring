## 两种类型的竞品价格监控软件（以及为什么划分很重要）

该领域的工具分为两类：基于订阅的监控仪表盘和原始抓取 API。选择正确的类别比选择品牌更重要，因为这两类工具解决的问题完全不同。

监控仪表盘处理一切事务：产品匹配、定时检查、价格变更告警和报告。您配置一次，即可查看结果。ScraperAPI 在频谱的另一端——它是一个抓取 API，负责获取价格数据并以干净的 JSON 格式交付，而产品匹配、告警和重新定价则由您自己实现。前期需要更多工作，但更灵活且随着规模扩大成本更低。

*   **仪表盘：** 适合小型产品目录、非技术团队，以及希望以最低成本获得价格提醒的用户。您为易用性付费，且通常按追踪产品数量付费。
*   **API：** 适合开发者和团队，他们需要在自有系统中处理大规模价格数据、应对反爬虫防线，且不介意编写脚本。

选择哪种方案更便宜取决于您的用量。我们将在计算实际数字后再做决定。

## 没人向您展示的积分计算方式：检查一次价格的真实成本

一个“请求”并非总是等于一个页面，且您监控的大多数电商网站价格高于基础费率。这是您在对比竞品价格监控软件时最重要的一件事，因为大多数工具按产品收费，而 ScraperAPI 按请求收费，不同请求的成本可能相差 75 倍。

官网的基准费率为：

*   **标准页面：** 1 积分
*   **Amazon, Walmart, eBay：** 5 积分
*   **Google, Bing（所有子域名）：** 25 积分
*   **LinkedIn：** 30 积分
*   **绕过反爬系统（Cloudflare, Datadome, PerimeterX, Akamai）：** 额外增加 10 积分

接着是参数。开启 `render=true` 进行 JavaScript 渲染，每请求增加 10 积分。在常规请求之上叠加 `premium=true`，每请求增加 10 积分。两者叠加则需要 25 积分。`ultra_premium=true`（最难的 IP 资源池）单独使用需 30 积分，配合渲染则需 75 积分——该组合仅限付费方案使用。同时，`country_code`、`session_number`、`output_format` 和 `autoparse` 则不额外收费。

算一下。在 Hobby 方案下，检查一个普通电商产品页面的价格在大多数情况下需要 5 积分（Amazon、Walmart 和 eBay 属于此列）。100,000 积分除以 5 = 每月约 20,000 次价格检查。对于拥有 500 个 SKU 的目录，意味着每天大约进行一次检查，共 40 天——这实际上能覆盖每月一次以上的完整目录扫描。如果您的目标站点位于 Cloudflare 防火墙之后且需要渲染，单次抓取成本约为 5 + 10 + 10 = 25 积分，同样的额度只够进行 4,000 次检查。

一份 2026 年的第三方评测（由 Xavier Fok 撰写的 proxyscraping.org）也表达了同样的观点：“如果你开启 JS 渲染去抓取 Amazon 搜索结果页面，1,000,000 积分可能只能覆盖 40,000 到 100,000 个实际页面，而非一百万。请根据真实的单页成本进行预算，而不是定价页面上的积分数量。”

好消息是，ScraperAPI 官方为您提供了按请求计算真实成本的实用工具：

1.  **域名成本估算器 (Domain Cost Estimator)** — 位于仪表盘内，可在启动前查询任意 URL 的积分成本
2.  **API Playground** — 在规模化运行任务前测试目标 URL 并查看实际积分用量
3.  一个成本端点 (`api.scraperapi.com/account/urlcost`)，接受与抓取请求相同的参数
4.  每个响应中的 `sa-credit-cost` 响应头，显示该请求的具体消耗量
5.  在每次抓取中设置 `max_cost`，确保单个请求不会超出您的预算

最后请注意计费规则：您仅需为成功的请求付费（HTTP 200 和 404 状态码）。但在 70 秒时限前主动取消的请求也是会计费的。在设置抓取超时参数时，请记住这一点。

## 您实际可以构建的内容：ScraperAPI 的价格监控功能

ScraperAPI 涵盖了您通常从专用监控器中获得的两大核心能力：大规模价格提取和定时数据收集，外加少量大多数仪表盘无法轻易实现的功能。

**结构化数据端点 (Structured data endpoints)。** ScraperAPI 没有提供原始 HTML 并强迫您编写解析器，而是为四个高价值目标维护了预设的电商端点——Amazon 产品和搜索、Walmart 搜索、Google Shopping 以及 eBay 产品。这些端点返回干净的 JSON 或 CSV 格式，包含价格、产品名称和其他字段，当目标网站重构 HTML 时，解析逻辑依然有效（无需自行维护）。官方展示的相同产品在不同渠道的价格说明了这种多站点对比的价值：一款 Fujifilm X-H2S 相机机身在 Amazon 某卖家处售价为 $2,499，另一家为 $2,229.95，而在 Google Shopping 中，B&H Photo 的标价为 $1,999.00。这类价差正是您进行价格监控的原因，一个端点即可呈现。

**DataPipeline。** 这是定时监控层：您可以设置每项目最多 10,000 个产品列表、查询或 URL 的抓取任务，通过 CRON 表达式定时执行，并通过 Webhook 将数据交付到您选择的位置——输出格式为 HTML 或转换为 JSON/CSV。配合异步抓取器（可在难以抓取的域名上并行发送数百万个请求），这就是为持续性价格监控而非一次性抓取所设计的底层架构。

**地理定位。** 所有方案均内置了 50 多个地理位置选项，在价格因国家而异的电商网站上非常有用。您可以通过 `country_code` 参数进行控制，且不会产生额外积分费用。

支持的底层架构包括 4000 万+ 个 IP，涵盖住宅、数据中心和移动资源池，支持轮换代理、自动重试以及验证码和反爬检测绕过——这些都是您在自建方案中需要费力搭建的基础设施。

## ScraperAPI 何时不是正确的工具

客观地说：有些场景下其他方案确实更合适，因此下文不会提供购买入口。

**您需要几百个 SKU 的邮件提醒。** 固定价格的监控器在这里明显更划算。根据目前公布的价格：PageCrawl 的 Standard 方案为 $8/月，覆盖 100 个页面且每 15 分钟检查一次；Altosight 起价约为 $49/月，包含产品匹配和告警；Pricefy 在 50 个 SKU 和 5 个竞争对手的配置下，年约合 $37/月（月付为 $49），支持每日更新；Prisync 起价约 $99/月；Price2Spy 起价约 $24/月。这些工具月付几十美元即可完成工作，无需编写任何代码。为您自己的产品匹配、告警和存储编写代码需要耗费工程工时，如果您的需求就是“产品价格变了就发邮件”，那这笔开销并不划算。

**您的目标站点有严格的防护且需要保持会话。** 第三方评测指出，在 LinkedIn 或受保护的电商网站进行大规模抓取时，`ultra_premium` 的乘数使得 ScraperAPI 比按带宽计费的专用住宅代理更贵。会话持久性（通过 `session_number`）设计用于单次抓取，而不是数小时的连续会话——如果您需要进行广告验证或长时间的账号工作流，这并非合适的工具。

**您想要一款零维护的产品。** ScraperAPI 处理代理、验证码和重试，但监控逻辑（计划任务、价格对比、告警）均需由您构建。对于真正不需要定制的买家来说，DataPipeline 和结构化端点可以减少大部分工作量，但依然不如订阅式仪表盘那样“开箱即用”。

## 常见问题

**ScraperAPI 如何针对被屏蔽或失败的请求计费？**
仅针对返回 HTTP 200 或 404 状态码的请求计费。连接错误、验证码死循环导致的失败以及超时请求不计费，但您在 70 秒时限前主动取消的请求会计费。达到并发上限的请求会收到 429 错误，同样不计费。

**credits 用完后会发生什么？**
默认情况下，抓取会暂停，直到您的积分更新。您可以开启自动升级（Hobby 到 Professional 方案）以自动切换到更高方案，或者如果您使用的是 Scaling 及以上方案，可以使用现付现用方式以固定费率继续抓取，直到达到您设定的月度上限。年付方案也可以提前续费以获取新的一批积分。

**免费试用真的免费吗？**
是的：为期 7 天，包含 5,000 API 积分，注册时无需信用卡。如果想延长测试时间，免费注册账户包含 1,000 积分和 5 个并发连接，如需额外测试积分，您可以联系客服。

**年付有优惠吗？**
每个方案均有 10% 的折扣——例如，Hobby 从 $49 降至 $44.10/月，Startup 从 $149 降至 $134.10/月。

**没有 Amazon 端点可以监控价格吗？**
有的，API 在任何网站上的工作方式都是一样的：发送 URL，获取页面（如果需要，可进行渲染），然后自行解析。预设的 JSON 端点是为了节省在 Amazon、Walmart、Google Shopping 和 eBay 上的解析工作量。任何其他电商网站都通过通用抓取器进行抓取，通常每页面消耗 1 积分，除非它有反爬保护。
